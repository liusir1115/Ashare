# 公网部署方案（简版）

## 1. 目标

当前先做本地 demo，后续再迁移为统一部署的 Web 系统。

最终目标是：

- 用户只需要打开网页
- 数据抓取统一在服务端完成
- 大模型调用统一在服务端完成
- 结果统一保存与导出
- 用户不需要自己安装 Python、AKShare 或配置代理

## 2. 为什么不走“每人本地安装”

如果每个人都本地运行，会有这些问题：

- Python 环境不一致
- AKShare 与依赖安装不一致
- 网络、代理、东方财富接口可达性不一致
- 非技术用户很难排查问题
- 后续更新和维护成本太高

所以长期一定要走统一部署。

## 3. 当前路线

推荐按四步走：

1. 本地 demo：先跑通完整业务闭环
2. 本地服务化：整理前后端接口、配置、日志和错误处理
3. 单机 Web 部署：让小范围朋友通过同一个网址使用
4. 正式公网部署：再补账号、权限、安全、监控和 HTTPS

## 4. 服务端负责什么

后续公网版本里，服务端统一负责：

- 行情与新闻抓取
- 数据清洗与结构化
- 市场总复盘生成
- 持仓复盘生成
- 操作复盘生成
- 大模型调用
- 结果保存与导出
- 降级提示与错误处理

## 5. 用户端负责什么

用户端尽量轻量，只负责：

- 打开页面
- 录入持仓
- 录入操作
- 查看复盘结果
- 发起问答
- 导出结果

## 6. 对当前本地 demo 的要求

虽然现在先做本地 demo，但代码结构要按以后可部署来约束：

- 前后端分离
- 数据抓取逻辑不要写死在页面里
- 大模型逻辑不要直接写在 UI 层
- 输出先生成结构化 JSON，再渲染页面和 Markdown
- 外部数据失败时要能明确降级

## 7. 当前结论

当前最合适的路线是：

1. 先把盘后模式做成本地可跑 demo
2. 本地 demo 结构按未来统一部署来设计
3. 验证通过后，再迁移到统一 Web 部署
