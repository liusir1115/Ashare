# 盘后本地 Demo 实施计划

## 文档定位

本文档用于说明盘后复盘模式在 `本地可跑 demo` 阶段的实施顺序、阶段目标、页面范围、数据准备、LLM 接入顺序和协作边界。

它回答：

- 盘后本地 demo 应先做哪些内容
- 哪些功能应分阶段落地
- 页面和数据应先打通哪一部分
- LLM 应该优先接入哪个任务
- 现有盘前产品基础如何复用

## 实施原则

盘后本地 demo 的实施遵循以下原则：

1. 先打通主链，再补细节
2. 先保证 `市场总复盘`，再完善 `持仓复盘` 与 `操作复盘`
3. 先保证结构稳定，再优化视觉和交互
4. 先复用既有盘前产品壳，再扩展盘后模式
5. 先做本地可跑版本，再考虑公网部署

## Demo 总目标

本地 demo 的目标不是一步到位做成完整产品，而是完成一条可验证的正式链路：

1. 拉取市场数据
2. 生成市场总复盘
3. 录入持仓
4. 录入操作
5. 生成持仓复盘
6. 生成操作复盘
7. 输出页面结果
8. 导出 Markdown

## 范围划分

### 本阶段必须完成

- 首页工作台
- 盘后复盘页
- 市场总复盘生成
- 持仓录入表单
- 操作录入表单
- 持仓复盘生成
- 操作复盘生成
- 页面展示
- Markdown 导出
- 盘后问答入口

### 本阶段可简化

- 历史记录页
- 复杂图表
- 多用户体系
- 权限管理
- 自动同步券商
- 手机端专项适配

### 本阶段明确不做

- 券商自动直连
- 自动同步实时持仓
- 自动同步当日成交
- 小程序
- 自动下单
- 回测联动

## 技术前提

当前盘后本地 demo 应尽量复用现有盘前项目基础：

- 前端壳
- 页面风格
- 基础后端服务
- 导出能力
- 数据源接入逻辑

新增部分应集中在：

- 盘后模式页面
- 市场复盘数据整理
- 持仓与操作输入表单
- LLM 调用层
- 盘后结果渲染层

## 页面实施顺序

### Phase 1：首页工作台

目标：

- 先搭一个进入盘后模式的入口页
- 提供今日状态与市场摘要

首版内容包括：

- 今日复盘状态
- 市场复盘摘要
- 个人复盘进度
- 持仓摘要
- 操作摘要
- 快捷入口
- 次日执行建议摘要

### Phase 2：盘后复盘页

目标：

- 承载完整盘后复盘 workflow

页面分区建议：

1. 市场总复盘区
2. 持仓录入区
3. 操作录入区
4. 持仓复盘结果区
5. 操作复盘结果区
6. 问答区
7. 导出区

## 数据实施顺序

### 第一优先级数据

优先打通市场总复盘所需数据：

- 指数表现
- 涨跌家数
- 成交额 / 量能
- 资金流向
- 涨停 / 跌停 / 炸板
- 连板结构
- 板块与方向候选
- 新闻摘要

### 第二优先级数据

为持仓和操作复盘准备上下文：

- 个股所属方向 / 板块
- 个股当日表现
- 个股资金强弱
- 个股在当日市场中的角色判断

### 第三优先级数据

后续增强项：

- 更细粒度的情绪数据
- 更稳定的新闻结构化摘要
- 更完整的方向映射

## LLM 接入顺序

盘后本地 demo 不建议一次性同时打通所有任务，而应按以下顺序接入：

### Step 1：市场总复盘任务

原因：

- 市场总复盘是整个盘后模式的地基
- 持仓复盘和操作复盘都依赖它
- 最容易先看出产品价值

### Step 2：持仓复盘任务

原因：

- 持仓复盘比操作复盘更稳定
- 它更接近“静态状态判断”，比逐笔动作归因更容易做好

### Step 3：操作复盘任务

原因：

- 它最依赖用户输入质量
- 也最依赖市场上下文和解释能力

### Step 4：盘后问答任务

原因：

- 问答需要建立在前三个任务的结果之上
- 放在最后接入最稳

## 推荐阶段计划

### Phase A：结构搭建

目标：

- 把页面壳和模式入口做出来
- 把盘后模式和盘前模式在产品内并列呈现

产出：

- 首页工作台占位
- 盘后复盘页占位
- 基础导航切换
- 风格统一

### Phase B：市场总复盘打通

目标：

- 用真实数据生成完整市场总复盘

产出：

- 市场总复盘结构化中间层
- LLM 市场总复盘任务
- 页面渲染
- Markdown 导出基础版

### Phase C：持仓录入与复盘

目标：

- 让用户能输入持仓并获得复盘结果

产出：

- 持仓录入表单
- 持仓上下文整理
- LLM 持仓复盘任务
- 持仓复盘页面区块

### Phase D：操作录入与复盘

目标：

- 让用户能输入操作并获得逐笔评价

产出：

- 操作录入表单
- 操作上下文整理
- LLM 操作复盘任务
- 操作复盘页面区块

### Phase E：问答与收尾

目标：

- 为当天复盘结果增加交互能力

产出：

- 盘后问答区
- 基于当天结果的问答上下文拼装
- 统一验收与失败提示

## 前后端边界建议

### 前端负责

- 模式切换
- 页面展示
- 表单录入
- 结果区渲染
- Markdown 导出触发

### 后端负责

- 数据抓取
- 结构化中间层生成
- LLM 调用
- 报告结构化结果生成
- 导出内容生成

## 与盘前模式的协作边界

当前建议采用：

- 盘前模式继续独立推进
- 盘后模式在现有项目中作为新模式接入

二者共享：

- 产品外壳
- 样式体系
- 基础服务
- 数据基础设施

二者分离：

- workflow
- 页面主内容
- LLM 任务
- 结果结构

## 最小可验证版本

盘后本地 demo 的最小可验证版本建议定义为：

1. 能进入盘后模式页面
2. 能自动生成市场总复盘
3. 能手动录入持仓
4. 能手动录入操作
5. 能分别生成持仓复盘和操作复盘
6. 能导出 Markdown

如果这 6 项完成，就可以认为盘后本地 demo 已成立。

## 当前协作建议

建议后续协作方式如下：

1. 先按本文档顺序做，不要并行发散
2. 每完成一个阶段，就回看是否满足最小可验证版本
3. 页面风格必须和盘前统一
4. LLM 输出必须经过结构验收和事实验收
