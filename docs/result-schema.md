# 结果结构说明

## 文档定位

本文档用于说明 AI 智能选股工具在结果展示、详情查看、历史记录和导出场景中的字段结构、必填要求和文案约束。

它回答：

- 结果页主列表显示哪些字段
- 个股详情页包含哪些信息
- 导出结果包含哪些内容
- 历史记录页保留哪些字段
- 哪些字段必须存在，哪些允许为空

## 结果结构总览

当前结果结构分为四类：

1. `结果页主列表`
2. `个股详情结构`
3. `历史记录结构`
4. `导出结构`

所有结果结构都应与以下原则保持一致：

- 首版以清晰、精简、可解释为优先
- 主列表用于快速查看排序结果
- 详情结构用于解释为什么这只股票排在这里
- 历史结构用于复盘和回看
- 导出结构用于轻量分享和归档

## 结果页主列表字段

结果页主列表字段包括：

1. `ranking`
   - 排名
2. `score`
   - 第二轮总分
3. `priority_label`
   - 优先级标签
4. `stock_code`
   - 股票代码
5. `stock_name`
   - 股票名称
6. `market`
   - 所属市场
7. `sector_tags`
   - 所属行业 / 概念
8. `first_round_match_summary`
   - 第一轮命中条件摘要
9. `second_round_reason_summary`
   - 第二轮核心理由摘要
10. `risk_summary`
    - 风险点摘要
11. `detail_entry`
    - 查看详情入口

设计要求如下：

- 主列表优先服务于快速扫榜
- 每行既能显示核心结论，也能进一步展开详情
- 主列表中的摘要不应冗长

## 个股详情结构

个股详情至少包含以下五个区块：

### 1. 基础信息

- `stock_code`
- `stock_name`
- `market`
- `sector_tags`

### 2. 第一轮命中情况

- `first_round_conditions`
  - 命中的筛选条件列表
- `first_round_metrics`
  - 各关键指标值
- `first_round_reason`
  - 第一轮入选说明

### 3. 第二轮排序解释

- `ranking_reason`
  - 排序原因
- `style_match_reason`
  - 风格匹配说明
- `theme_and_catalyst_reason`
  - 催化与题材说明
- `risk_reason`
  - 风险提示

### 4. 第二轮评分摘要

- `score`
- `priority_label`
- `dimension_summary`
  - 主要维度简要结论

### 5. 数据说明

- `data_sources`
  - 本次结果依赖的数据源
- `trading_date`
  - 交易日
- `degraded_fields`
  - 是否存在缺失或降级维度

## 导出结构

首版支持以下导出格式：

- `Excel`
- `Markdown`

首版导出粒度采用：

- `主列表 + 每只股票的简要解释`

说明如下：

- 不仅导出纯列表
- 不导出过重的完整详情结构
- 导出结果应适合日常归档与分享

导出内容至少包括：

- 排名
- 分数
- 优先级标签
- 股票代码
- 股票名称
- 所属行业 / 概念
- 第一轮命中条件摘要
- 第二轮核心理由摘要
- 风险点摘要

## 历史记录结构

历史记录页每条记录至少包括：

1. `record_date`
   - 日期
2. `mode`
   - 盘前 / 盘后模式
3. `market_scope`
   - 股票范围
4. `condition_summary`
   - 条件摘要
5. `first_round_count`
   - 第一轮命中数
6. `final_result_count`
   - 第二轮展示数
7. `degraded_flag`
   - 是否降级运行
8. `view_entry`
   - 查看结果入口
9. `export_entry`
   - 导出结果入口

首版历史记录页不强制展示：

- 前 3 名摘要

## 字段必填与可空规则

## 不允许为空的字段

以下字段在正式结果中不允许为空：

- `ranking`
- `score`
- `stock_code`
- `stock_name`
- `first_round_match_summary`
- `second_round_reason_summary`
- `data_sources`
- `trading_date`

原因如下：

- 这些字段缺失会直接破坏结果可读性与可信度
- 若这些字段无法生成，通常意味着结果不应被视为正式输出

## 允许为空的字段

以下字段允许为空，但必须符合降级提示规则：

- 个股热度相关信息
- 龙虎榜 / 游资机构信息
- 某些增强解释字段
- 增强评分明细

## 文案长度约束

首版结果文案以精简为原则。

长度建议如下：

- 主列表中的 `second_round_reason_summary`
  - `1 到 2 句话`
- 主列表中的 `risk_summary`
  - `1 句话`
- 详情页中的四段解释
  - 每段 `1 到 3 句话`

文案要求如下：

- 先说结论，再补原因
- 避免长篇背景介绍
- 避免看似专业但无法解释排序的空话

## 结果页顶部摘要字段

结果页顶部摘要区建议保留以下字段：

- `mode`
  - 盘前 / 盘后模式
- `market_scope`
  - 股票范围
- `condition_summary`
  - 条件摘要
- `first_round_count`
  - 第一轮命中数
- `final_result_count`
  - 第二轮展示数

以下字段属于可后置项：

- 任务运行时间
- 数据更新时间
- 更细粒度评分维度明细

## 降级运行标识

当系统因非核心数据缺失而降级运行时，结果结构中必须保留降级标识。

至少应支持以下信息：

- 是否发生降级
- 缺失的是哪些维度
- 对结果可能造成的影响范围

## 后续扩展位

以下结果结构能力保留为后续扩展：

- 更完整的维度分项评分
- 分享链接结构
- 图片导出结构
- 历史对比结果结构
