# 项目需求说明

## 文档定位

本文档用于说明当前 AI 智能选股工具的正式业务目标、用户范围、核心主链、数据边界和需求约束。

它回答：

- 这个项目要解决什么问题
- 谁会使用它
- 当前正式主链覆盖哪些场景
- 当前版本明确做什么、不做什么
- 数据从哪里来，失败时如何处理
- 第一版以什么形态落地

## 项目目标

当前项目是一个面向个人与小范围朋友使用的 A 股盘前/盘后智能选股 Web 工具。

项目目标包括：

1. 提供一条从用户提出选股需求到输出最终候选股票排名结果的最小可运行业务主链。
2. 解决现有 AI 选股数据来源不透明、结果不准的问题。
3. 弥补传统条件选股工具过于死板、结果为 0 时无法继续优化的问题。
4. 将第一轮技术面硬筛与第二轮情绪面排序结合，形成更接近真实交易观察的候选结果。
5. 以正式文档、真实数据源、清晰规则和可解释结果为基础，支持后续持续迭代。

## 角色与用户类型

当前正式用户包括：

- `primary_user`
  产品拥有者本人，具备一定市场经验，希望提升盘前准备与盘后复盘效率。
- `friend_user`
  小范围朋友用户，使用方式与主用户相似，但不作为复杂权限体系的设计前提。
- `admin`
  系统管理员，负责账号创建、基础配置和系统维护。

当前版本以 `账号登录` 为访问入口，不接微信、不接短信、不做公开注册。

## 核心业务场景

当前正式主链覆盖以下业务场景：

1. 用户登录 Web 页面，进入选股工作台。
2. 用户选择盘前或盘后模式。
3. 用户通过指标面板设置第一轮硬性筛选条件，或在后续版本中通过自然语言生成候选条件。
4. 系统基于真实财经数据执行第一轮量化筛选，得到初步股票池。
5. 若第一轮结果过多，系统建议缩窄条件；若结果过少或为 0，系统提示用户调整策略并给出建议方向。
6. 系统将第一轮股票池送入第二轮情绪排序模块。
7. 第二轮结合新闻催化、板块热度、资金流向、市场情绪、风格切换等维度进行打分和排序。
8. 系统输出前 10 名候选结果，并允许查看完整榜单和每只股票的详细分析卡。
9. 系统保存当日选股结果，供用户回看、导出或分享给受邀用户。

## 当前正式范围

当前版本正式支持以下范围：

- Web 页面形态
- 账号登录
- 多用户共享同一系统
- 每个用户拥有自己的查询历史和结果数据
- 盘前选股
- 盘后复盘选股
- 指标面板手动选股
- 第一轮结果交互式优化
- 第二轮排序与解释
- 新闻摘要
- 板块热度分析
- 市场风格总结
- 当日结果保存
- 结果导出

## 当前不做什么

当前正式主链明确不包含以下能力：

- 小程序形态
- 自动交易
- 盘中实时监控
- 公开注册与商业化订阅
- 复杂角色权限体系
- 自然语言直接驱动正式筛选作为首版核心入口
- 多策略保存与策略市场
- 历史回测正式模块
- 外部开放 API 平台
- 用 mock/demo 数据冒充真实选股结果

## 第一轮技术选股模块

该模块负责根据用户输入的量化条件，对 A 股市场执行第一轮硬性筛选，生成初步候选股票池。

正式约束如下：

- 股票范围支持用户选择，默认范围为 `沪深主板 + 创业板`
- 股票范围下拉项首版包括：`沪深主板`、`沪深主板 + 创业板`、`科创板`
- 默认排除项包括：`ST / *ST`、`停牌股`、`上市 90 天以内新股`、`北交所`
- 支持排除项一键全部排除
- 第一轮仅支持 `日线级别`
- 系统架构需为后续接入更多数据源和更高频周期预留扩展接口
- 指标输入方式以 `区间输入` 为主
- 条件设置支持 `下拉选择`
- 单次组合条件建议控制在 `3 到 6 个`
- 若结果过多，系统自动建议缩窄条件
- 若结果过少，系统提示适当放宽条件
- 若结果为 0，系统进入交互式优化流程，提示可能存在条件过严或条件冲突，并给出具体调整方向

首版量化指标包括：

- 股价区间
- 总市值区间
- 流通市值区间
- 涨跌幅区间
- 近 N 日涨幅区间
- 近 N 日回撤区间
- 换手率区间
- 成交额区间
- 成交量放大倍数
- 振幅区间
- 持续放量 / 缩量
- 均线位置
- 均线突破
- N 日新高 / N 日新低
- 连续上涨 / 连续下跌天数
- 筹码集中度
- 所属行业 / 概念
- 基础排除条件组合

第一轮结果展示字段包括：

- 股票代码
- 股票名称
- 所属市场
- 所属行业 / 概念
- 命中的指标条件
- 关键数值
- 第一轮入选说明

## 第二轮情绪排序模块

该模块负责对第一轮候选股票池进行二次打分与排序，输出最终观察结果。

正式约束如下：

- 第二轮输出形式为 `排名 + 分数`
- 分数采用 `100 分制`
- 排序机制采用 `规则打分为主，大模型负责解释`
- 默认展示前 `10` 名，同时允许查看完整榜单
- 即使第一轮仅筛出少量股票，第二轮仍需完成完整排序与解释
- 盘前与盘后允许使用不同解释模板

首版必做维度包括：

- 新闻催化
- 板块热度
- 资金流向
- 市场情绪
- 风格切换
- 龙头带动
- 涨停 / 连板结构
- 题材扩散度

首版可选增强维度包括：

- 个股热度
- 龙虎榜 / 机构游资参与度

每只股票默认解释内容包括：

- 为什么排在这个位置
- 为什么更匹配当前市场风格
- 当前热点或催化因素是什么
- 主要风险点是什么

## 输入与交互方式

当前版本输入方式以 `指标面板` 为主。

交互要求如下：

- 用户可手动设置区间型条件
- 条件项支持下拉选择
- 条件冲突时系统必须提示
- 结果过多、过少、为 0 时，系统必须主动引导优化
- 自然语言生成筛选条件作为后续增强项保留接口，但不作为 v0.1 核心依赖

## 数据源选型与成本策略

当前数据源策略如下：

- `v0.1 主数据源`：`AKShare`
- `v0.1 历史研究辅助源`：`Baostock`
- `v0.2 预留升级源`：`Tushare Pro`
- `东方财富直连/第三方选股 skill`：后续增强项，不作为 v0.1 核心依赖
- `聚合数据`：不作为主链数据源

成本策略如下：

- v0.1 以 `零或低成本` 为原则
- 优先使用 AKShare 跑通真实数据版 MVP
- 若 MVP 体验成立，再评估接入 `Tushare 5000 积分档`
- 暂不采购 `Tushare 新闻 1000 元/年` 权限
- 财经新闻优先通过 AKShare 可接入的东财、财联社、同花顺、新浪等公开资讯源聚合获取

## 数据可用性与失败处理

系统必须把自己当作正式产品设计，禁止以演示数据掩盖真实失败。

正式约束如下：

- 禁止使用 mock/demo 数据冒充真实结果
- 所有选股结果必须展示 `数据源`、`交易日`、`更新时间`
- 系统启动时必须执行数据健康检查
- 选股请求前必须检查本次依赖的数据维度是否就绪
- 核心数据缺失时，系统必须中止结果输出并提示 `数据不完整`
- 非核心数据缺失时，系统允许降级，但必须明确提示缺失维度和影响范围
- 需要记录接口失败原因，包括权限问题、时效问题、上游波动、字段映射异常等

## 结果保存与共享

当前版本结果管理要求如下：

- 至少保存当日选股结果
- 用户拥有自己的查询历史和结果
- 支持导出结果
- 系统支持多用户共享访问
- 访问方式采用 `公网可访问 + 白名单账号登录`
- 暂不做公开分享链接，后续可扩展

## 当前业务约束

- 正式结果仅基于真实数据生成
- 第一轮是硬筛，第二轮是排序，二者职责边界必须明确
- 第一轮不混入主观情绪判断
- 第二轮必须能解释排序理由
- 页面展示层不直接拼装伪数据作为兜底
- 数据源配置、更新时间、交易日口径必须统一
- 盘前与盘后模式可以共用框架，但解释模板和部分权重允许不同
- 系统需预留后续接入大模型自然语言筛选、历史回测、盘中监控等扩展点
