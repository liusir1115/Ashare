# 盘后复盘需求说明

## 文档定位

本文档用于定义 A 股智能选股产品中的 `盘后复盘模式`，明确其目标用户、业务主链、输入输出、功能范围与阶段边界。

它回答：

- 盘后复盘模式要解决什么问题
- 谁会使用它
- 一次完整的盘后复盘由哪些步骤构成
- 当前版本做什么、不做什么
- 与盘前模式是什么关系

## 项目背景

当前产品分为两个正式模式：

1. `盘前模式`
   用于开盘前完成候选股票筛选与观察列表生成。
2. `盘后模式`
   用于收盘后完成市场复盘、持仓分析、操作复盘以及次日执行准备。

其中：

- 盘前模式已有 demo 基础，继续由既有路线推进
- 盘后模式属于全新能力，单独设计 workflow
- 盘后模式不再沿用盘前模式“同一筛选逻辑仅调整权重”的思路，而是采用：
  `市场总复盘 -> 持仓复盘 -> 操作复盘 -> 次日执行建议`

## 项目目标

盘后复盘模式的目标包括：

1. 生成一份对当日 A 股市场有结构、有证据、有结论的正式复盘报告
2. 帮助用户理解当天市场主线、次主线、活口、失败轮动和风险边界
3. 支持用户手动录入持仓信息，生成针对持仓的复盘分析
4. 支持用户手动录入当日操作记录，生成针对交易动作的复盘分析
5. 输出次日的观察重点、回避方向和执行建议
6. 形成一个先本地 demo 可跑、后续可统一部署为 Web 产品的盘后模式基础

## 当前阶段前提

当前阶段以 `本地可跑 demo` 为前提设计。

这意味着：

- 当前版本优先确保在单机环境下完成完整盘后复盘链路
- 页面形态仍按 Web 产品方式设计
- 后续可迁移到统一部署的共享系统
- 当前阶段不要求每个用户都本地运行
- 当前阶段重点是验证产品结构、数据链路和 LLM 复盘能力

## 目标用户

当前正式用户包括：

- `primary_user`
  产品拥有者本人，具备一定市场经验，希望通过系统化复盘提升交易判断和执行质量。
- `friend_user`
  小范围朋友用户，希望后续可通过统一网页使用盘后复盘能力。
- `admin`
  系统维护者，负责环境、账号、基础配置和部署。

当前版本默认服务对象为：

- A 股个人投资者
- 偏短线、波段或主动交易型用户
- 需要通过盘后复盘为次日做准备的用户

## 核心业务主链

盘后复盘模式的正式主链如下：

1. 系统在收盘后拉取市场所需数据
2. 系统生成当日 `市场总复盘`
3. 用户进入盘后模式，查看市场总复盘摘要与完整报告
4. 用户手动录入或更新个人持仓信息
5. 系统结合市场总复盘与持仓数据生成 `持仓复盘`
6. 用户手动录入当日操作记录
7. 系统结合市场总复盘、持仓与操作数据生成 `操作复盘`
8. 系统输出次日观察重点、回避方向和执行建议
9. 系统保存本次复盘结果，支持后续查看与导出

## 核心能力拆分

盘后模式由三段核心能力组成：

### 1. 市场总复盘

目标：

- 给出对整体市场的正式结论
- 判断今天的主线、次主线、活口、失败方向和风险边界
- 提供可追溯的数据证据

### 2. 持仓复盘

目标：

- 判断用户当前持仓是否仍匹配市场主线和风格
- 判断哪些持仓顺势、哪些持仓偏弱、哪些持仓属于风险观察对象
- 给出条件式的次日关注建议

### 3. 操作复盘

目标：

- 评价用户当日买卖动作是否合理
- 判断是否符合市场环境、节奏与个人原本计划
- 总结典型错误和改进方向

## 大模型角色

盘后模式从第一天起就是一个 `LLM 驱动的复盘产品`。

大模型承担的职责包括：

- 收口
- 裁定
- 解释
- 建议
- 问答

大模型不承担的职责包括：

- 直接抓取原始行情
- 在缺失数据时自行编造事实
- 绕过结构化输入直接生成不受约束的长篇结论

## 当前正式范围

当前版本正式支持以下范围：

- 市场总复盘
- 用户手动录入持仓
- 用户手动录入操作记录
- 持仓智能复盘
- 操作智能复盘
- 次日执行建议
- 围绕当天复盘结果的问答能力
- 页面展示
- Markdown 导出
- 与盘前模式统一的产品风格

## 当前不做什么

当前正式主链明确不包含以下能力：

- 券商账户自动直连
- 自动同步实时持仓
- 自动同步当日成交
- 盘中实时复盘
- 自动下单
- 高频策略
- 小程序优先形态
- 多用户复杂权限体系
- 回测联动
- 复杂图表分析
- 每个用户本地都独立安装一套环境后再使用的产品模式

## 输入方式

当前版本输入由两部分组成：

### 1. 系统自动输入

由系统统一拉取：

- 当日市场行情
- 资金流向
- 板块数据
- 涨停 / 连板结构
- 新闻与快讯

### 2. 用户手动输入

#### 持仓录入

字段包括：

- 股票代码 / 名称
- 成本价
- 当前仓位
- 持仓天数
- 当前盈亏
- 持仓理由（可选）
- 计划持有逻辑（可选）

说明：
- 除持仓理由外，其余核心字段尽量完整

#### 操作录入

字段包括：

- 股票代码 / 名称
- 买入 / 卖出方向
- 成交价
- 仓位变化
- 操作时间
- 操作理由
- 操作预期（可选）
- 结果评价自述

说明：
- 操作复盘要求完整记录
- 关键字段缺失时不生成正式操作复盘结果

## 输出结构

盘后模式的输出结果至少包括三份结构化结果：

1. `市场总复盘报告`
2. `持仓复盘报告`
3. `操作复盘报告`

它们共同组成一次完整的盘后复盘会话。

统一输出要求如下：

- 结构固定
- 语言精简
- 结论优先
- 证据可追溯
- 支持导出与保存

## 页面结构

当前版本采用两个页面：

1. `首页工作台`
2. `盘后复盘页`

### 首页工作台

负责：

- 今日复盘状态
- 市场复盘摘要
- 个人复盘进度
- 持仓摘要
- 操作摘要
- 快捷操作入口
- 次日执行建议摘要

### 盘后复盘页

负责：

- 完整市场总复盘
- 持仓录入
- 操作录入
- 持仓复盘结果
- 操作复盘结果
- 围绕当日复盘内容的问答
- Markdown 导出

## 当前业务约束

1. 市场总复盘必须先于持仓复盘和操作复盘生成
2. 持仓复盘和操作复盘必须依赖当日市场复盘上下文
3. 用户输入不足时，系统只能输出有限结论，不能强行补全不存在的信息
4. 系统必须区分“数据事实”和“AI 解释”
5. 报告必须标明交易日和数据来源
6. 操作复盘要求完整字段后才能提交分析
7. 页面与交互风格必须与既有盘前模式保持统一
8. 系统应预留后续迁移为统一部署 Web 产品的能力

## 与盘前模式的关系

盘前模式和盘后模式属于同一产品下的两个正式模式。

二者共享：

- 同一产品定位
- 同一视觉和交互风格
- 同一数据基础设施
- 同一结果保存体系
- 后续同一部署形态

二者不同：

- 盘前模式以 `筛选候选机会` 为目标
- 盘后模式以 `生成复盘与次日准备` 为目标
- 盘后模式是 LLM 驱动型模式，逻辑不依附于盘前排序体系

## 后续待讨论事项

以下内容已识别，但暂未在 v0.1 最终定稿：

- 大模型接入的具体供应商与调用方式
- 结构化中间层的数据 schema
- 持仓复盘和操作复盘的 prompt / skill 模板
- 未来从本地 demo 迁移为统一部署系统的实施路径
