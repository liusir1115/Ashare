# 盘后复盘 LLM 设计说明

## 文档定位

本文档用于定义盘后模式中大模型的职责、任务拆分、输入输出结构、事实边界、验收机制和模板预留方式。

它回答：

- 大模型在盘后模式中负责什么
- 盘后模式的大模型任务如何拆分
- 每个任务分别吃什么输入、吐什么输出
- 如何限制模型幻觉
- 如何为后续 Prompt / Skill 模板沉淀打基础

## 大模型角色

盘后模式从第一天起就是一个 `LLM 驱动的复盘产品`。

大模型承担的职责包括：

- 收口
- 裁定
- 解释
- 建议
- 问答

大模型不承担的职责包括：

- 直接抓取原始行情
- 对缺失数据自行编造事实
- 跳过结构化输入直接生成自由长文

## 任务拆分

盘后模式拆成 4 个独立 LLM 任务：

1. `市场总复盘生成`
2. `持仓复盘生成`
3. `操作复盘生成`
4. `盘后问答`

设计原则如下：

- 不采用一个超级大任务一次性生成全部内容
- 通过任务拆分保持输入清晰、输出稳定、便于调试
- 各任务之间通过结构化结果衔接

## 输入形式

所有 LLM 输入都采用：

`结构化中间层 -> LLM`

而不是将原始 DataFrame、接口字段或前端页面内容直接喂给模型。

## 一、市场总复盘任务

### 输入结构

市场总复盘任务的输入包由以下 5 组对象组成：

1. `market_environment`
   - 交易日
   - 上证 / 深成 / 创业板表现
   - 涨跌家数
   - 成交额
   - 量能变化
   - 涨停家数
   - 跌停家数
   - 炸板家数
   - 封板率
   - 连板高度

2. `fund_flow_summary`
   - 行业 / 板块净流入前列
   - 行业 / 板块净流出前列
   - 个股净流入前列
   - 个股净流出前列
   - 资金方向裁定基础证据

3. `rotation_summary`
   - 主线候选方向
   - 次主线候选方向
   - 活口候选方向
   - 失败方向候选
   - 每个方向的代表股与基础强弱证据

4. `sentiment_summary`
   - 连板结构
   - 高低位承接
   - 回封 / 炸板情况
   - 情绪锚个股
   - 情绪阶段候选判断

5. `news_summary`
   - 今日重要新闻摘要
   - 板块催化新闻
   - 个股催化新闻
   - 与主线相关的政策 / 事件摘要

### 输出结构

市场总复盘任务固定输出：

- `one_line_summary`
- `environment_section`
- `fund_flow_section`
- `top_cards`
- `rotation_section`
- `sentiment_section`
- `why_section`
- `next_day_plan`

## 二、持仓复盘任务

### 输入结构

持仓复盘任务的输入包包括：

1. `market_review_summary`
   - 一句话总收口
   - 今日主线
   - 今日次主线
   - 风险边界
   - 次日重点
   - 情绪判断

2. `holdings_list`
   - 股票代码 / 名称
   - 成本价
   - 当前仓位
   - 持仓天数
   - 当前盈亏
   - 持仓理由
   - 计划持有逻辑

3. `holding_contexts`
   - 所属方向 / 板块
   - 是否接近主线
   - 今日涨跌表现
   - 资金表现
   - 是否属于情绪强票 / 弱票 / 活口 / 边缘方向
   - 与今日主线和风险边界的关系

### 输出结构

持仓复盘任务固定输出：

- `portfolio_overall_review`
- `holding_reviews`

其中：

#### `portfolio_overall_review`

包括：

- 整体持仓评价
- 整体风险判断
- 明日整体关注点

#### `holding_reviews`

每只持仓输出：

- `holding_positioning`
- `market_fit`
- `current_status`
- `risk_points`
- `next_day_watch`

## 三、操作复盘任务

### 输入结构

操作复盘任务的输入包包括：

1. `market_review_summary`
   - 使用市场总复盘结论摘要

2. `operation_list`
   - 股票代码 / 名称
   - 买入 / 卖出方向
   - 成交价
   - 仓位变化
   - 操作时间
   - 操作理由
   - 操作预期
   - 结果评价自述

3. `operation_contexts`
   - 操作发生时所属方向
   - 当天市场所处阶段
   - 该股是否顺主线
   - 该股当日表现
   - 是否处于高风险 / 高拥挤 / 活口 / 失败方向
   - 与当日主线和风险边界的关系

### 输出结构

操作复盘任务固定输出：

- `operation_overall_review`
- `operation_reviews`

其中：

#### `operation_overall_review`

包括：

- 整体执行评价
- 典型问题总结
- 改进方向

#### `operation_reviews`

每笔操作输出：

- `environment_fit`
- `timing_judgement`
- `execution_consistency`
- `problem_diagnosis`
- `improvement_suggestion`

## 四、盘后问答任务

### 输入结构

问答任务输入包括：

- `market_review_result`
- `holding_review_result`
- `operation_review_result`
- `user_question`

说明：

- 问答必须建立在当天复盘结果之上
- 不允许脱离当天上下文做泛化投顾式回答

### 输出结构

固定输出：

- `answer`
- `cited_basis`
- `uncertainty_note`

其中：

#### `answer`

- 直接回答用户问题

#### `cited_basis`

- 说明回答依据的是哪部分复盘内容

#### `uncertainty_note`

- 当信息不足或问题超出上下文时，必须说明不确定性

## 事实边界

以下规则作为统一硬约束：

1. 模型不能编造不存在的数据
2. 模型不能把缺失字段说成明确事实
3. 模型必须区分：
   - `事实层`
   - `解释层`
4. 信息不足时必须允许输出：
   - 信息不足
   - 结论有限
   - 需要次日验证

## 验收机制

盘后模式的 LLM 输出必须经过验收，而不是“模型说完成就算完成”。

### 一、结构验收

检查是否包含必需字段与章节。

### 二、内容验收

检查正文是否非空、是否存在明显空话或占位内容。

### 三、事实一致性验收

检查是否引用了不存在的数据，是否将缺失信息写成已确认事实。

### 四、行为验收

检查模型是否完成其该完成的职责，例如：

- 市场复盘是否给出主线 / 次主线 / 风险边界 / 次日重点
- 持仓复盘是否给出整体评价和单票评价
- 操作复盘是否给出整体评价和逐笔评价
- 问答是否基于当天复盘上下文

### 验收状态

验收结果统一为三种状态：

1. `pass`
   - 验收通过，可作为正式输出
2. `degraded`
   - 基本可用，但存在缺项或降级说明
3. `fail`
   - 不可作为正式输出，必须重试或返回错误

## Prompt / Skill 模板预留

从第一天起预留以下 4 套模板：

1. `市场总复盘模板`
2. `持仓复盘模板`
3. `操作复盘模板`
4. `问答模板`

每套模板至少包含以下 5 类内容：

1. `任务目标`
2. `输入说明`
3. `硬约束`
4. `输出结构`
5. `禁止事项`

## 统一禁止事项

以下禁止事项应写入所有模板：

- 不得编造不存在的数据
- 不得把缺失数据说成确定事实
- 不得输出与结构不符的自由长文
- 不得省略次日建议或风险提示
- 不得脱离当日复盘上下文做空泛投顾式表达
