# Version 3 结构化筛选与交互收口开发记录

## 版本定位

Version 3 在 Version 2 的真实数据源接入基础上，继续完善“前端结构化输入 -> 后端参数校验 -> 历史结果回看”的可维护链路。
这一版不引入数据库，也暂不继续扩展盘前 / 盘后策略差异，而是优先解决当前版本里最容易产生误解和不稳定的部分：自由文本条件输入、后端参数容错、前端重复逻辑以及历史结果页未打通的问题。

这一版聚焦于以下事情：
1. 将前端自由文本条件改为结构化控件，数值输入只允许填写数字。
2. 为 `/api/screen/run` 增加更严格的参数校验与报错返回。
3. 打通本地 `result` 目录与历史结果页面的联动。
4. 清理前端展示逻辑与联调逻辑的重复部分，改成更单一的职责分工。
5. 保持现有 AKShare 快筛和历史增强链路可继续运行。

## 已确认设计方向

- 当前版本所有参与筛选的输入项统一改为结构化控件，不再依赖“数字 + 中文”的自由文本解析。
- 数值型筛选使用 `number input`，区间提示、单位提示放在字段标题区域，而非放在输入框内。
- 历史增强指标只在 `screen_depth = full` 时生效；前端会将这部分控件显示为“增强项”。
- 行业 / 概念与筹码集中度仍未正式接入，本版只在界面中明确显示为“待接入，不参与筛选”。
- 历史结果页读取本地 `result/*.xlsx`，而不是继续展示静态占位记录。
- 前端保留展示页气质，但联调逻辑统一由 `api-bridge.js` 承担，避免旧展示脚本与真实请求互相干扰。

## Version 3 包含内容

### 前端筛选控件结构化
- 重写 [index.html](D:/学习工作区/Ashare/frontend/index.html)
- 将原来的自由文本条件改为结构化输入卡片，包括：
  - 股价区间
  - 总市值区间
  - 流通市值区间
  - 涨跌幅区间
  - 近 N 日涨幅区间
  - 近 N 日回撤区间
  - 换手率区间
  - 成交额区间
  - 量比区间
  - 振幅区间
  - 均线位置
  - 均线突破
  - 新高 / 新低
  - 连续涨跌
  - 放量 / 缩量
- 所有区间项都改为显式的最小值 / 最大值输入。
- 需要“天数 + 范围”的条件改为三段式数值输入。
- 连续涨跌条件改为“方向下拉框 + 最小天数 + 最大天数”。
- 对未接入的行业 / 概念、筹码集中度条件做禁用说明，不再伪装为可用输入项。

### 前端样式与交互优化
- 更新 [styles.css](D:/学习工作区/Ashare/frontend/styles.css)
- 新增结构化筛选卡片样式：
  - `control-card`
  - `control-head`
  - `range-inputs`
  - `triple-inputs`
  - `quad-inputs`
- 为“仅增强模式生效”的条件增加弱化展示状态。
- 让条件摘要实时根据当前结构化输入刷新。

### 前端联调逻辑收口
- 重写 [api-bridge.js](D:/学习工作区/Ashare/frontend/api-bridge.js)
- 不再使用正则从自由文本里抽数字。
- 改为根据 `data-filter`、`data-bound`、`data-day-field` 等结构化标记读取表单值。
- 统一由 `api-bridge.js` 负责：
  - 组装后端 payload
  - 调用 `/api/screen/run`
  - 更新结果表格
  - 更新右侧详情抽屉
  - 更新结果摘要
  - 更新加载状态
  - 更新数据源状态
  - 刷新历史结果列表
- 将 [app.js](D:/学习工作区/Ashare/frontend/app.js) 收口为展示层脚本，仅负责：
  - 盘前 / 盘后文案切换
  - 页面跳转
  - 抽屉关闭

### 后端参数校验增强
- 重写 [service.py](D:/学习工作区/Ashare/akshare_backend/service.py)
- 新增 `PayloadValidationError`
- 在 `normalize_payload()` 中接入严格校验逻辑
- 增加以下校验：
  - `mode` 只能为 `pre` / `post`
  - `screen_depth` 只能为 `fast` / `full`
  - `market_scope` 必须为受支持的市场范围
  - 区间项必须是 `[min, max]`
  - 区间下限不能大于上限
  - 非负区间不能输入负数
  - `days`、`min_days`、`max_days` 必须是正数
  - 连续涨跌方向只能为 `up` / `down`
  - 历史增强枚举值必须落在当前支持集合里
- 对 `fast` 模式自动清空历史增强项，避免前端误传导致逻辑混乱。

### 历史结果页打通
- 在后端新增 `/api/history`
- 新增 `list_saved_results()`，从 `result` 文件夹读取最近的 xlsx 结果文件
- 历史结果页现在可展示：
  - 执行时间
  - 盘前 / 盘后模式
  - 执行深度
  - 市场范围
  - 本地文件名
- 前端支持手动刷新历史记录列表

### 现有数据链路保持可用
- 保留 Version 2 中的：
  - AKShare 实时快照拉取
  - DataFrame 快筛
  - 历史 K 线增强
  - Excel 结果落盘
- 本轮执行后新增验证结果文件：
  - [2026-05-05_16-56.xlsx](D:/学习工作区/Ashare/result/2026-05-05_16-56.xlsx)

Version 4 建议进入以下方向：
1. 正式接入行业 / 概念映射，让结果页不再显示占位文本。

4. 优化 AKShare 历史增强耗时，补充更清晰的缓存策略和降级说明。
5. 将 Excel 导出与 Markdown 导出从“提示入口”变成真正的文件输出能力。
